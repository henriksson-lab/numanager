# Driver Evidence Register

This register is the audit checklist for deciding whether a driver feature is
ready to expand. A driver may exist with configured local-state behavior, but
new hardware behavior should not be added unless the evidence basis below is
strong enough for the specific command, property, completion rule, or safety
state.

Hardware validation notes should follow
[`hardware-validation-template.md`](hardware-validation-template.md) so support
claims include device identity, evidence sources, observed completion, safety
behavior, and remaining uncertainty.
For protocol-evidence targets waiting on transport details, collect traces using
[`../reverse/trace-capture-guide.md`](../reverse/trace-capture-guide.md) before
changing the expansion status or adding a default SDK-free driver. The trace
must be paired with console/runtime output and, where applicable, hardware
output/readback for the same action window.

| Evidence class | Meaning |
| --- | --- |
| Public standard | Protocol is defined by a public standard or standard-like specification |
| Manufacturer protocol | Commands are documented by the original manufacturer |
| Open firmware/source | Behavior is traceable to public firmware, headers, open SDK source, or audited open adapter source |
| Hardware trace | Behavior is traceable to captured traffic or a bench note |
| Fixture/local only | Useful for runtime shape, but not sufficient evidence for protocol expansion |

## Rules For Updating

| Change | Required update |
| --- | --- |
| Add a driver family | Add a row here and a device page under `docs/devices/` |
| Add a protocol command | Cite the source class in the device page and update the missing-evidence field if it changes |
| Validate hardware | Add the hardware model, firmware, transport, and observed completion/fault behavior to the device page |
| Add tests | Do not generate hardware-driver tests. Record protocol assertions in evidence notes, trace notes, or hardware-validation records unless a specific externally evidenced validation workflow explicitly requires executable checks |
